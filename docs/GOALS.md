# 原型目標

## 主要目標

建立一個非常小型的 2D 戰棋 RPG 原型，只專注在核心遊戲邏輯。

第一版暫不規劃動畫、角色圖、音效或美術打磨。

## 第一個可玩目標

- [x] 有一個 8x8 棋盤。
- [x] 棋盤上放置一個玩家單位與一個敵方單位。
- [x] 玩家可以選取自己的單位。
- [x] 玩家可以將選取的單位移動到有效的空格。
- [x] 玩家可以在相鄰時攻擊敵人。
- [x] 敵人可以執行非常簡單的回合。
- [x] 遊戲可以判定勝利或失敗。

## 第二個可玩目標

重點是從單一單位原型推進到基礎戰術決策。

- [x] 加入明確的回合狀態。
- [x] 允許玩家單位移動後，若敵人在攻擊範圍內則可以攻擊。
- [x] 加入第二個玩家單位與第二個敵方單位。
- [x] 在棋盤上顯示簡單的單位 HP 資訊。
- [x] 選取玩家單位時，高亮顯示有效移動格。

## 第三個可玩目標

重點是驗證三個基礎職業是否能產生可觀察的戰術差異。

目標不是完成最終戰鬥平衡。第一版數值刻意保持簡單，評估重點應放在遊玩時是否能觀察到職業定位。

完成條件：

- 可以建立戰士、弓箭手、法師單位，並顯示在戰鬥中。
- 三個職業使用 `docs/VISION.md` 裡的原型數值表。
- 戰士、弓箭手、法師的移動力都固定為 3。
- 攻擊規則支援最小與最大射程。
- 戰士普通攻擊射程為 1。
- 弓箭手普通攻擊射程為 2-3，且不能攻擊相鄰敵人。
- 法師普通攻擊射程為 1。
- 普通攻擊使用原型傷害、命中、暴擊與最低傷害規則。
- 法師有 MP，且可以使用普通攻擊。
- 法師有一個單體法術與一個十字範圍法術，並使用原型技能規則。
- 法師技能無視防禦、不做命中判定，且不能暴擊。
- UI 顯示足夠的 HP、MP、職業與行動回饋，以支援測試。
- 敵方 AI 可以維持簡單，但不能破壞基本戰鬥流程。

驗證問題：

- 玩家是否自然地把戰士放在前線附近？
- 玩家是否會因為相鄰敵人會造成問題，而嘗試讓弓箭手保持距離？
- 玩家是否會在不同情境下，選擇法師普通攻擊、單體法術或十字法術？
- MP 是否讓玩家有明確理由不要每次都施法？
- 初始數值是否足以呈現職業差異，即使還沒有完全平衡？

### 第三個可玩目標實作計畫

用小而可審查的步驟實作這個目標。每一步在進入下一步前，都應保持專案可建置。

#### 1. 職業資料基礎

狀態：已於 2026-06-12 完成。

範圍：

- 加入戰士、弓箭手、法師的職業識別。
- 加入符合 `docs/VISION.md` 原型數值的職業定義表。
- 保持既有戰鬥流程不變。

完成條件：

- 單位可以被指定職業。
- 單位 HP、MP、攻擊、防禦、命中係數、迴避、移動力、暴擊率與普通攻擊射程可以從職業資料推導。
- 既有單位仍會顯示，且可以正常進行回合。

不包含：

- 命中擲骰。
- 暴擊擲骰。
- 法師技能。
- UI 重新設計。

#### 2. 單位數值整合

狀態：已於 2026-06-15 完成。

範圍：

- 更新單位狀態以保存目前 HP 與目前 MP。
- 透過單位或職業定義，保留最大 HP、最大 MP、攻擊、防禦、命中係數、迴避、移動力、暴擊率與普通攻擊射程。
- 用三個原型職業初始化玩家與敵方單位。

完成條件：

- 戰鬥配置使用戰士、弓箭手、法師資料，而不是硬編碼攻擊與移動值。
- 移動仍能運作，且移動力固定為 3。
- 既有簡單攻擊仍能運作，即使在戰鬥公式步驟前暫時保留舊的固定傷害行為。

不包含：

- 完整戰鬥公式。
- 技能選擇。
- 狀態效果。

#### 3. 攻擊射程規則

狀態：已於 2026-06-15 完成。

範圍：

- 將只允許相鄰攻擊的檢查，替換為最小與最大攻擊射程。
- 套用普通攻擊射程：
  - 戰士：1。
  - 弓箭手：2-3。
  - 法師普通攻擊：1。

完成條件：

- 戰士可以攻擊相鄰敵人。
- 弓箭手可以攻擊 2-3 格外的敵人。
- 弓箭手不能攻擊相鄰敵人。
- 法師可以普通攻擊相鄰敵人。
- 無效射程嘗試會顯示清楚的狀態訊息。

不包含：

- 攻擊射程高亮。
- 敵方 AI 的射程意識，除非需要避免破壞基本戰鬥流程。

#### 4. 普通攻擊公式

狀態：已於 2026-06-23 完成。

範圍：

- 實作普通攻擊命中判定、迴避、暴擊機率、暴擊傷害與最低傷害。
- 使用 `docs/VISION.md` 裡的原型公式。

完成條件：

- 普通攻擊傷害為 `attack - defense`，最低 1。
- 命中率為 `攻擊者命中係數 - 防禦者迴避`，下限 0%，上限 95%。
- 暴擊機率使用職業表數值，不加額外修正。
- 暴擊傷害在基礎傷害計算後，再乘以 1.5。
- 狀態文字清楚顯示命中、未命中、傷害與暴擊結果，足以支援測試。

不包含：

- 戰鬥預測 UI。
- 保存 RNG 狀態。
- 平衡調整。

#### 5. 基礎 UI 回饋

狀態：已於 2026-06-24 完成。

範圍：

- 顯示足夠的單位資訊，以支援職業差異測試。
- 優先使用簡單文字，而不是精緻 UI。

完成條件：

- 單位顯示 HP。
- 法師單位顯示 MP。
- 單位以最小但可讀的方式顯示職業識別。
- 狀態文字說明失敗行動、傷害結果、未命中、暴擊與 MP 不足。

不包含：

- 完整角色面板。
- 詳細戰鬥預測。
- 動畫或視覺打磨。

#### 6. 單位行動狀態、模式與選單

重點是先補上更接近 SRPG 的單位行動流程，再加入技能。

設計方向：

- 單位選取後可以選擇移動、攻擊或待機。
- 移動與攻擊各最多一次。
- 移動後回到行動選單。
- 攻擊後回到行動選單。
- 移動與攻擊都完成後，自動待機。
- 待機是單位待機，不是結束整個玩家回合。
- 待機後不能再次選取該單位。
- 後續技能會接在這個行動模式上。

##### 6A. 新增單位行動狀態概念

範圍：

- 保留並沿用 `HasAttackedThisTurn`。
- 新增 `HasWaitedThisTurn`。
- 新增 `CanMoveThisTurn`，由 `RemainingMovePoints` 與待機狀態推導。
- 新增 `CanAttackThisTurn`，由攻擊與待機狀態推導。
- 新增 `MarkWaited()`。
- `StartTurn()` 重設移動力、攻擊與待機狀態。

完成條件：

- 現有 gameplay 行為不變。
- 目前移動仍照 `RemainingMovePoints` 運作。
- 目前攻擊仍照 `HasAttackedThisTurn` 運作。
- `CanMoveThisTurn` 與 `CanAttackThisTurn` 先作為後續流程使用，暫不替換現有 resolver 行為。
- 專案可建置。

##### 6B. 新增待機

範圍：

- 讓單位可以進入待機狀態。
- 第一版可以先用鍵盤或暫時流程觸發待機，不要求正式 UI。

完成條件：

- 待機後清除選取單位。
- 待機後不能再次選取該單位。
- 新玩家回合開始時解除待機。
- 待機不會結束整個玩家回合。
- `End Turn` 仍維持原本結束整個玩家回合的功能。

##### 6C. 選取單位後用模式決定點擊行為

範圍：

- 加入移動模式與攻擊模式。
- 第一版可以先用鍵盤切換模式。

完成條件：

- 選取單位後預設移動模式。
- 移動模式下點空格只嘗試移動。
- 攻擊模式下點敵人只嘗試攻擊。
- 移動模式點敵人不攻擊。
- 攻擊模式點空格不移動。
- 狀態文字顯示目前模式或無法行動原因。

##### 6D. 顯示可攻擊範圍

範圍：

- 在攻擊模式下高亮普通攻擊範圍。

完成條件：

- 戰士顯示相鄰格。
- 弓箭手顯示 2-3 格，且不包含相鄰格。
- 法師普通攻擊顯示相鄰格。
- 第一版不考慮障礙物。

##### 6E. 簡單行動選單 UI

範圍：

- 用畫面按鈕取代鍵盤切換移動、攻擊與待機。

完成條件：

- 選取玩家單位時顯示 Move、Attack、Wait。
- 已用過的行動會 disable 或不顯示。
- 點擊 Wait 後該單位待機。

不包含：

- 主動技能。
- 被動技能。
- 技能選單。
- 技能射程預覽。

#### 7. 法師 MP 與技能選擇

範圍：

- 加入一個最小方式，讓法師單位選擇普通攻擊、單體法術或十字法術。
- 法師技能使用時消耗 MP。
- 套用共用的法師技能規則。

完成條件：

- 法師仍可以使用普通攻擊。
- 單體法術消耗 3 MP，射程 3，造成 `法師攻擊 + 4`，無視防禦，不會未命中，且不能暴擊。
- 十字法術消耗 4 MP，射程 3，造成 `法師攻擊 + 1`，無視防禦，不會未命中，且不能暴擊。
- MP 不足時不能使用技能。

不包含：

- 大型技能選單。
- 技能快捷鍵。
- 技能射程預覽。

#### 8. 十字法術範圍結算

範圍：

- 將十字法術範圍解析為目標格，以及上下左右各 1 格。
- 對受影響格子中的所有敵方單位造成傷害。

完成條件：

- 十字法術可以擊中多個敵人。
- 空的受影響格會被忽略。
- 第一版不影響友方單位。
- 已被擊敗的敵人會被後續行動忽略。

不包含：

- 友軍傷害。
- 複雜範圍預覽。
- 障礙物阻擋範圍效果。

#### 9. 狀態效果基礎

範圍：

- 加入暫時性狀態效果的資料結構。
- 實作持續時間處理規則，但不要求立即使用所有規劃中的狀態。

完成條件：

- 單位可以持有狀態效果。
- 同一種狀態效果不能堆疊。
- 重新套用同一狀態會重置剩餘持續時間。
- 狀態效果會立即套用。
- 狀態效果在持有者回合結束時遞減。
- 狀態效果在剩餘 0 回合時移除。

不包含：

- 完整 buff/debuff 技能組。
- 嘲諷 AI 行為。
- 完整處理所有暈眩邊界情境。

#### 9. 第三個可玩目標驗證

範圍：

- 執行專案檢查。
- 進行足夠的手動測試，以回答驗證問題。
- 更新文件記錄學到的內容。

完成條件：

- `dotnet format SRPG_practice.sln --verify-no-changes` 通過。
- `dotnet build SRPG_practice.sln` 成功。
- `docs/PROGRESS.md` 記錄已實作與已驗證的內容。
- 任何後續平衡或 AI 工作都有記錄；除非破壞核心流程，否則不阻擋此目標完成。

## 待辦清單

### 1. 建立棋盤

- [x] 建立 8x8 格子。
- [x] 每個格子應該可以被點擊。
- [x] 使用簡單彩色矩形或 Godot 預設節點。
- [x] 目前不需要格子美術。

### 2. 建立基礎單位資料

- [x] 建立一個玩家單位。
- [x] 建立一個敵方單位。
- [x] 每個單位需要：
  - 格子位置
  - HP
  - 攻擊力
  - 移動範圍
  - 隊伍

### 3. 顯示單位位置

- [x] 在棋盤上顯示玩家單位。
- [x] 在棋盤上顯示敵方單位。
- [x] 使用不同的簡單顏色區分隊伍。

### 4. 選取玩家單位

- [x] 點擊玩家單位所在格會選取該單位。
- [x] 在遊戲狀態中保存選取的單位。
- [x] 使用 console log 或簡單標籤作為回饋即可。

### 5. 移動玩家單位

- [x] 選取玩家單位後，點擊空格會嘗試移動。
- [x] 只允許移動到移動範圍內。
- [x] 只使用曼哈頓距離。
- [x] 不允許斜向移動。
- 目前不實作地形消耗。

### 6. 攻擊敵人

- [x] 如果玩家單位與敵人相鄰，點擊敵人會攻擊。
- [x] 依照玩家攻擊力降低敵人 HP。
- [x] 敵人 HP 為 0 或以下時移除敵人。

### 7. 結束玩家行動

- [x] 玩家移動或攻擊後，結束玩家行動。
- 第一版維持只有一個玩家單位。
- 目前不實作行動點數。

### 8. 加入簡單敵方回合

- [x] 如果敵人與玩家相鄰，敵人會攻擊。
- [x] 否則，敵人會在自己的移動範圍內朝玩家移動。
- [x] 目前不實作完整尋路。
- [ ] 後續敵方 AI pass：當朝目標的直接步伐被佔用時，嘗試其他有效移動選項，而不是立刻停止。

### 9. 加入勝敗判定

- [x] 如果敵人 HP 到達 0，顯示勝利狀態。
- [x] 如果玩家 HP 到達 0，顯示失敗狀態。

### 10. 保持第一版簡單

- 第一版 gameplay 實作維持在 `Main.cs`。
- 只有當邏輯變得難以閱讀後，才拆分成 `Board.cs`、`Unit.cs` 或 `TurnManager.cs` 之類的檔案。
